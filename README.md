# 百度知道答题助手 v2（zhidao-answer-studio）

> 🌐 **在线展示站**：https://66666666218.github.io/baiduzhidao/ （架构图 / 模拟演示 / 文档导航；演示需本机跑 node site/server.js）

围绕百度知道活动页的全自动答题流水线：**爬题入库 → 随机抽题 → AI 生成回答 → 自动提交 → 通过数核对**。
v2 为重构版：分层架构、选择器集中、单源存储、任务引擎统一、零依赖单测 + 全链路 E2E。

> 旧版（v1）分析与新旧对比见 `docs/开发文档.md`。

## 环境要求

- Node.js ≥ 20（开发机 26）
- 比特浏览器客户端（开启"本地设置 → API"，默认 `http://127.0.0.1:54345`）
- AI：任意 OpenAI 兼容接口（默认硅基流动，需自行充值 API Key）

## 快速开始

```bash
npm install                # 已配 npmmirror + Electron 镜像
npm run mock               # 可选：启动本地模拟站（无账号体验/调试）
npm start                  # 启动桌面应用
npm run smoke              # 冒烟自检：加载渲染端 + 点遍界面上所有按钮，抓处理器体内的错误
npm test                   # 单元测试（500+ 条，含"新电脑环境"守卫）
npm run test:e2e           # 全链路 E2E（需本机有 Edge，无需账号）
npm run selftest           # 一键自检 CLI（不开应用验证整条链路）
npm run dist               # 打包成安装包 → dist/（改完代码**必须重打包**才生效，见下）
npm run verify:package     # ⚠️ 发版必跑：验真产物（版本号 / 生产依赖是否真在包里 / undici ≤6）
npm run verify:release     # ⚠️ 发版必跑：验 latest.yml 的 sha512/版本号是否与安装包一致 + 三件套指纹
```

> **改了代码但运行起来还是老样子？** `dist/` 里放的是历史构建产物（已被 .gitignore 忽略），
> 开发时 `npm start` 直接跑源码；要让**安装版**也生效，必须重新 `npm run dist`。

> **为什么必须有 `npm run verify:package`**：`require("undici")` 能跑通**不等于**它被打进了安装包。
> 2026-10-14 实测过这一幕：`node_modules/undici` 的 `package.json` 丢了，源码里 `require` 照样成功
> （Node 会退到 `index.js`）、全部单测全绿，但 electron-builder 收集依赖靠的就是那个 `package.json` ——
> 于是**连着好几个安装包里都没有 undici**，代理功能静默退化成直连。单测守不住这种事（它跑在源码树上），
> 只有直接查 asar 才看得见。
>
> **为什么还要 `npm run verify:release`**：`latest.yml` 里的 `sha512` 一旦和安装包对不上，
> 客户端下载完**校验会失败** —— 表现就是用户说的"点了更新但是更新不了"，而且**不报错**。
> 另外版本号不 bump 的话，客户端按版本比较会直接认为"已是最新"（也不会报错）。
> 这两条都是"发了等于没发"，所以固定在发版尾巴上跑一遍，顺带打出三件套 sha256
> 用来和 GitHub 线上的 `assets[].digest` 逐一比对（比下载 85MB 回来再算快得多）。


## 功能视图（与 v1 对应）

| 视图 | 功能 | 说明 |
|------|------|------|
| 比特环境 | API 地址、账号列表、全局参数、**一键自检** | 自检=模拟站+无头Edge 7 步全链路，零配置 |
| 题目爬取 | 进入答题区→锁定分类→逐页逐题记录标题+链接 | 预载题库去重；**断点续爬**；脏数据防护；按钮失效自动切题卡直提取 |
| **题库浏览** | 关键字搜索 + 分类筛选 + 分页 + 链接直达 | 万条题库秒查 |
| 随机抽题 | **多分类勾选**随机抽 N 题 → xlsx | 跨轮去重，抽完自动重置；表格路径自动记忆；**取消保存不消耗额度**；显示可抽/已抽 |
| 生成答案 | 批量 AI 生成，并发/热更新/失败跳过/行去重 | 结果写回表格；token 用量统计；**日预算上限**；回答质检告警 |
| 复制答案 | 记录搜索、分页、一键复制、导出、清理 | 支持账号打码 |
| 自动提交 | 账号轮换、每日限额、跳过已提交、提交前达标检测、**成功信号确认** | **有封号风险，需确认** |
| 常用网址 / 运行日志 | 快捷链接 / 结构化日志 | 日志落盘并自动清理 30 天前旧文件 |

**数据安全**：所有任务运行中逐条追加 CSV 自动保存（`运行缓存/autosave/`），Excel 被占用或进程崩溃都不丢记录；退出时强制落盘。

## 能力边界（这个项目能做什么 / 不能做什么）

**能做：**
- ✅ 零配置自检：安装后点"一键自检"即可验证引擎、浏览器自动化、模拟 AI、提交流程全部可用
- ✅ 全自动爬题：指定分类从活动页逐页采集题目（标题+链接），断点续爬、跨次去重
- ✅ 批量 AI 回答生成：任何 OpenAI 兼容接口，可配并发，自动写回 Excel 表格
- ✅ 半自动答题：生成答案 → 一键复制 → 人工粘贴提交（零封号风险路径）
- ✅ 全自动提交（高风险）：多账号轮换、每账号每日限额、跳过已提交、跳过已达标账号
- ✅ 答题过程留痕：题库/答案/进度/AI 用量全部本地落盘，日志可追溯

**不能做 / 未做：**
- ❌ 不能保证百度页面结构不变——改版后需更新 `pages/selectors.js`（有模拟站回归测试兜底）
- ❌ 不能绕过百度风控——遇到安全验证会停下等人工处理，不会尝试自动打码
- ❌ 不做账号注册、养号、自动解封
- ❌ 不做除百度知道活动页以外的平台（知乎/头条等需要另写页面适配器）
- ❌ 不承诺回答质量——AI 生成内容有质检告警但建议人工复核后再提交
- ❌ 没有云端同步/多机协作——单机单实例设计，数据在本地

## 一键全自动（两种入口）

**入口一：软件内「⚡ 一键全自动」页** —— 勾阶段、点一下，全程无人值守。

**入口二：`每日跑批.bat`** —— 无头跑，适合挂计划任务。

```
答题链  ① 爬题（四分类） → ② 抽题 → ③ AI 生成答案 → ④ 自动提交
网盘链  ⑤ 转存（脚本套模板生成问答） → ⑥ 按题材拆表 → ⑦ 分账号上传
```

两步可分开勾选。网盘链里 ⑤ 的产出（上传专用表）会**自动喂给** ⑥，不用再选一次文件。

```bash
每日跑批.bat                             # 双击跑完整条链，日志落 运行缓存/logs/
node scripts/daily-batch.js 20           # 只跑 ②③④，本批 20 条
node scripts/upload-by-topic.js 表.xlsx  # 只跑 ⑥⑦
```

- 账号取自设置页「比特环境名称」，**全部账号参与提交/上传**；环境变量 `ZHIDAO_BIT_ENV` 可覆盖
- 提交是否执行由设置页「自动提交」开关决定：**关 = 只生成不提交**
- 每账号上限取自设置页「每账号每日限额」
- 任一阶段失败即停，前面已完成的成果保留；软件里点「停止」会中止后续阶段

**两阶段账号策略（题材路由）**

| 阶段 | 内容 | 路由方式 |
|------|------|----------|
| 前期 · 积累额度 | 普通答题（纯文本答案） | 账号**不限**题材，轮询摊到全部账号 |
| 后期 · 上传资源 | 上传专用表（含网盘链接） | 按**分类规则**派生题材，账号 ↔ 题材**严格一对一** |

**上传侧的分类规则**（设置页可编辑）：每行 `分类名=关键词1|关键词2`，从上到下**先命中先分类**，
都未命中则该行本次不上传。内置游戏/影视/小说/漫画/音乐/课程/软件/资料 8 条。
规则里 `app`/`mod`/`ape` 这类短英文词按**词边界**匹配，不会把 `apple`/`model`/`shape` 误分类。

账号题材绑定同样在设置页配（每行一个 `账号=题材`）。未绑定的账号不参与该阶段上传。

分类的产出形式是**一个题材一张表**——拆出来的分表存在源表同级的「分表」目录，可以人工过目后再传。
这样做不是往上传表里加列：上传模板是平台约定的，多一列风险是整批被拒收。

## 网盘资源供给链路（10 万目标 · 供给端）

```
①采集（三选一或并行）
  ├─ scripts/pan-crawl-batch.js     关键词池批量爬取（去重/断点/限速）
  ├─ scripts/panlay-collect.js      panlay.com 投稿流 / 关键词搜索（--search 消耗 200/天配额）
  └─ scripts/panlay-login.js        panlay.com 登录（人工一次，会话常驻）
                 ↓ 主资源库（追加式，崩溃不丢）  <数据目录>/pan-resources-master.jsonl
                 ↓ 导出两列表                    <数据目录>/pan-resources-master.xlsx
②转换  scripts/pan-to-qa.js        两列 → 六列问答格式（质量门槛）

③转存确权 ← 关键一步：别人的分享随时可能失效，必须转存到自己网盘、再用「自己的链接」出问答
  └─ 四条路线，按可靠性/速度取舍（**同一批别混着跑**）：
     · scripts/pan-transfer-batch.js     纯 HTTP 协议版 —— 最快，脚本跑批首选
     · scripts/pan-transfer-pipeline.js  浏览器执行器版 —— 五阶段，**设计上就是串行**（共用 Cookie 罐）
     · scripts/pan-transfer-ui.js        真 UI 点击版 —— 最可靠，API 直连被风控时用它
     · scripts/netdisk-share-existing.js 网盘里**已有**的文件直接建分享（不转存）
                 ↓ 上传专用表-第N批-M条.xlsx（qid / 问题标题 / 回答内容）

④上传  scripts/workbench-upload-per-account.js  按账号批量上传（每日额度自适应）
```

```bash
# 例：把一份资源表转存确权成可上传的问答表（结果会自动打印落盘目录）
node scripts/pan-transfer-batch.js --input=资源.xlsx --limit=50
# 采集 1 小时（断点续爬，可反复跑）
node scripts/pan-crawl-batch.js --minutes=60
```

**跑完去哪看结果？** 脚本结束时会自己打印，不用猜：
- `上传专用表: <目录>` —— 产物 xlsx 的位置（默认 `<数据目录>/transfer-batch/<表名>/上传专用表/`）
- `状态文件: <目录>/state.jsonl` —— 断点续传台账；**重跑会自动跳过已完成的**，不会重复转存或重复上传
- 汇总行 `本轮转存成功 X | 失败 Y | 历史累计可用问答 Z`
- 特别地，「已转存但没生成分享链接」会**单独告警**（文件在你的网盘里，但没有链接就出不了问答），
  并指明原因（账号达每日 300 分享上限 / 该资源被百度禁止二次分享）——这不是失败，明天或换号重跑即可补上。

## 出错代码（errno）速查

跑批日志里出现 `errno=...` 时对照这张表；**不要**看到报错就换账号或放弃这一条：

| errno / 现象 | 含义 | 该怎么做 |
|---|---|---|
| `2` | 目标目录不存在（偶发也会因**容量不足**误报） | 自动回落顶层目录重试；整批频繁出现先查网盘容量 |
| `4` | 已转存过 | **视为成功**，复用已有文件（重跑不会重复占空间） |
| `115` | 该资源**被百度禁止二次分享** | 永久性，换账号/等明天都没用 → 只放弃这一条，**别封账号** |
| `120` / "分享次数已达上限" | 该账号**当日 300 个分享**额度用完 | 换账号，或明天重跑；**会自动封该账号本批剩余项** |
| `12` / `-10` | 容量不足 | 只废这个账号，其余账号继续 |
| `-6` | 登录失效 | 去软件里重新登录该账号 |
| `-62` / `-65` / `-70` | 触发风控 | 全局暂停 10 分钟（脚本自动等），降速重跑 |
| `-9` | **端点相关**：verify 阶段 = 提取码错误 | 看阶段；不要当成容量不足 |
| 出现"分享页限流" | 打太快，不是链接失效 | 脚本自动冷却 3 分钟再继续 |
| 连续 10 条失败 | 大批量异常 | 脚本自动停止，可稍后重跑续传（已完成的不会重做） |

## 换电脑 / 数据放在哪

所有运行时数据（题库、设置、`cdp.txt`、转存台账、导出的表格、日志）都在**一个数据目录**里：

| 场景 | 数据目录 |
|---|---|
| 开发模式（`npm start`） | 项目里的 `运行缓存/` |
| 打包版（安装到 C 盘） | `%APPDATA%\zhidao-answer-studio`（**是另一份数据**） |
| 自定位置 | 设环境变量 `ZHIDAO_DATA_DIR` 指过去 |

⚠️ **`运行缓存/` 被 .gitignore 忽略 —— 新电脑 clone 下来没有这个目录，里面也没有你的数据。**
所以：

- 脚本需要比特浏览器 CDP 端口（`运行缓存/cdp.txt`），这个文件由软件里的「连接比特浏览器」写入，
  **不在 git 里**。新电脑上先开比特浏览器 → 在软件里点「连接比特浏览器」，再跑脚本。
  找不到时脚本会给出可照着做的提示，不是裸 `ENOENT`。
- **想让脚本直接读写打包版那份数据**，就先设：`set ZHIDAO_DATA_DIR=%APPDATA%\zhidao-answer-studio`
  （`每日跑批.bat` 顶部有注释掉的现成一行，取消注释即可）。
- **搬家**：把整个数据目录拷到新电脑的同一位置即可；或拷到别处再设 `ZHIDAO_DATA_DIR`。
- **验证「换电脑能不能跑」**：`node scripts/simulate-fresh-machine.js --run`
  —— 它把源码复制到临时目录（**不含** `运行缓存/`、`.git/`）后跑全套测试，证明不依赖本机残留。

## 用真实比特浏览器联调

1. 打开比特浏览器 → 本地设置 → 开启 API
2. 应用内"比特环境"页填 API 地址（默认即可）和账号名称（每行一个）→ 测试连接
3. 题目爬取 → 开始爬取（首次建议先爬 1 页验证）
4. 生成答案页填 API Key → 开始生成
5. 复制答案或配置自动提交（建议先 1~2 条试水）

## 风险提示

- 自动提交违反百度知道平台规则，有触发风控、封号的可能，请自行评估
- 比特浏览器用于多账号防关联，请遵守当地法律法规
- 本项目仅供学习研究
