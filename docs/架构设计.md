## 2. 任务状态机（v2.1-①）

```
PENDING → RUNNING → SUCCESS
                 → FAILED（含原因）
                 → CANCELLED（用户停止）
RUNNING ⇄ PAUSED（协作式：任务在 ctx.pausePoint() 检查点挂起）
```

- 迁移经 `transition()` 校验，非法迁移抛错；全程 `task.stateChanged` 事件
- TaskManager 保留最近 50 条任务快照（`historyList()`）
- `updateLiveSettings()` 热更新（修复 v1 缺失该方法导致 settings:save 报错的潜在 bug）

## 3. 事件系统（v2.1-⑦）

EventBus 支持三类订阅：精确（`answer.generated`）、前缀通配（`task.*`）、全量（`*`）。
当前事件域：`task.*`（生命周期）、`pipeline.*`（阶段）、`answer.*`、`submission.*`、`account.*`。
订阅方：运行日志（UI+文件）、审计日志（JSONL 按天，`dataDir/audit/`）。

## 4. 流水线（v2.1-③）

`Pipeline` 阶段数组执行器：链式传递（`previous` 集合）、阶段事件、失败即停（异常带阶段名）、
断点续跑（`checkpoint.load/save`，跳过的阶段向下游传 null）。首个消费者为一键自检（8 阶段）。
核心任务（爬/生成/提交）的流水线化是 v2.2 方向。

## 5. 数据模型（v2.1-②）

Question 生命周期：
```
DISCOVERED → READY → ANSWERING → ANSWERED → (REVIEW_REQUIRED → APPROVED)?
                  ↘ ANSWER_FAILED（可重试回 ANSWERING）
→ SUBMITTING → SUBMITTED / SUBMIT_FAILED（可回 REVIEW_REQUIRED）
```
- `questionFingerprint`：URL pathname（剥离 activity 参数）+ 标题哈希 → 跨参数去重
- `toQuestionModel`：旧 bank/answers 记录零破坏升级（lifecycle 推断：submittedAt→SUBMITTED、
  质检问题→REVIEW_REQUIRED、有回答→ANSWERED、否则 READY）
- 迁移到 SQLite（v2.5）时以 fingerprint 为主键即可

## 6. 质量门（v2.1-⑥）

七项检查：长度 / Markdown 残留 / AI 痕迹与敏感词 / 标题复读 / 相关性（bigram 重叠启发）/ 重复度。
输出 `{ decision: PASS|REVIEW, score: 0-100, checks, issues }`；硬伤（空/过短/风险词）直接 REVIEW，
软性扣分 score<60 → REVIEW。结论写入表格"质检"列；REVIEW 表示"不要自动提交，先人工复核"。

## 7. LLM 分层（v2.1-⑤）

```
generate task → LlmClient（并发闸/退避重试/记账） → Provider（HTTP 传输） → 平台 API
             ↘ Strategy（answer：模板渲染/消息构造/清洗）
```
- 供应商预设识别 `describeProvider()`（硅基流动/DeepSeek/OpenAI/通义/智谱/本地）
- 换供应商 = 换 baseUrl/model 配置或新增 provider 文件；业务与 tasks 零改动
- 模型路由（按分类/长度选模型）为 v2.5 方向，接口已就绪（strategy 可按 item 选择）

## 8. 账号策略（v2.1-④）

`AccountManager`：register/acquire/release/markBlocked/unblock。
- acquire 校验封禁与每日额度（错误码 ACCOUNT_BLOCKED / ACCOUNT_QUOTA_EXCEEDED）
- 今日用量以 answers 存储已提交记录为准 + 进程内偏移
- 跨账号严格隔离；提交任务的轮换限额仍由 allocateRowsToEnvs 承担（AccountManager 接管为 v2.2 方向）

## 10. 演进路线（与总纲对齐）

- **v2.2**：三大核心任务迁移到 Pipeline 阶段化；AccountManager 接管提交轮换；暂停检查点嵌入长任务
- **v2.5**：SQLite（以 fingerprint 为主键）+ Repository；Contract Test（BrowserAdapter/LlmProvider 双实现同套契约）；真实成功信号持续校准
- **v3.0**：Platform Adapter（core 与百度解耦，页面适配器成为平台插件）
