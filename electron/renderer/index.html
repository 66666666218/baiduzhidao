比特环境与全局设置

运行模式（由你选，软件不替你决定）：

• 纯协议：内存几乎为零，上传一批只要 0 秒（窗口模式要 6 秒）。代价是所有账号共用本机 IP 和同一份网络指纹 —— 想隔离就配下面的「账号代理」（每个账号一个出口 IP，比指纹隔离更实在）。
• 比特窗口：每个环境一套指纹，隔离最彻底；代价是内存（每窗口几百 MB）。
• Edge 无头：内存介于两者之间，但所有账号共用同一份 Edge 指纹。
注意：Cookie 里不含指纹 —— 从比特提取的 Cookie 跑纯协议时不会带上比特的指纹；要真正用上比特的隔离，就得选「比特窗口」模式。

带链接的答案按此表严格一对一投递；没绑定的账号不会收到链接答案。纯文本答案不受此表限制。

用于把「上传专用表」按题材拆给各账号：每行按问题标题派生题材，再交给绑定了同名题材的账号上传。整行以 # 开头视为注释。

纯协议模式下所有账号共用本机 IP。想让每个账号走不同出口 IP 就在这里配（支持 http/https/socks5）。IP 隔离比指纹隔离更实在；不填就是直连，与以前完全一样。左边账号名要与「比特环境」里的名字一字不差。

⚠️ 只有在你已经给每个账号配了不同出口 IP（上面的「账号代理」）时才建议调高。 同一个 IP 上并发操作多个账号，是平台风控最敏感的一类特征；调高并发等于主动把自己摆到那个特征上。
• 纯协议模式：不开窗口，内存几乎不涨，但所有账号共用本机 IP —— 没配代理就别调高。
• 比特窗口模式：会同时开这么多个比特窗口，请把这些账号的窗口都留着、并确认内存够用（每个窗口几百 MB）。
建议从 2 开始，观察一两天再加；软件上限为 10。设成 1 时行为与以前完全一样（顺序执行）。

写什么就搜什么（不会自动拼「网盘」）。题材名要与「账号题材绑定」里的一致；没配搜索词的题材本次不搜。纯协议采集，不需要浏览器和登录态。

只管逐题提交那条链（自己设的风控护栏，与平台额度无关）。网盘上传不受它约束。

使用教程

🚀 新用户三步上手（先看这个）

  1. 设置页把「运行模式」选「① 纯协议」（默认就是）—— 最快最省内存，全程不开浏览器。
  2. 到「账号凭证」页，给每个账号点「登录并提取」：弹出的窗口里扫码或用账号密码登录百度， 登进去窗口会自动关闭并入库。每个账号只做一次。
  3. 到「一键全自动」页勾好阶段，点开始。

这么做之后：爬题、提交、上传、查收录、网盘转存全都不需要浏览器。 下面的「比特浏览器」章节只在你想用指纹隔离时才需要（设置页把运行模式改成「② 比特窗口」）。

🔧 比特浏览器环境配置（每个账号一个环境）

  1. 在比特浏览器里新建环境，名称建议直接用账号名（如 测试组1、测试组2）。 软件「比特环境」页里填的环境名必须和这里一字不差，差一个字就找不到窗口。
  2. 必须在这个环境里登录百度账号——这是最容易漏、也最容易被误判成"配置坏了"的一步。 打开环境 → 访问 zhidao.baidu.com → 右上角登录。 登录成功后这个环境的 Cookie 里才会有 BDUSS；没登录的环境虽然也能打开百度知道首页， 但答题入口、活动页、工作台都会失效。
    转存网盘还要再登录一次 pan.baidu.com（同一账号，登录后 BDUSS 和 STOKEN 都会带上）， 否则转存时会提示"该账号无网盘登录态"并跳过。
  3. 代理留空即可（直连）。若要用代理，务必确认它能访问百度——代理不通的表现同样是"页面打不开"， 容易和别的毛病混在一起。
  4. 回到软件「比特环境」页，把环境名填进「比特环境名称」（每行一个），点测试连接确认能连上比特 API。

❓ 环境像"打不开百度知道"——先看这三条

  1. 百度知道是客户端渲染的，页面要等十几秒才出内容。 刚打开时是空白壳：实测同一个问题页 2 秒时只有 4.6KB，12 秒后才渲染出完整内容（1.38MB）。 等一会儿再看，那不是打不开。
  2. 没登录就没有答题入口。未登录环境打开百度知道首页是正常的， 所以光看首页会误以为没问题；真正需要账号的地方（活动页 / 工作台）才会失效。 判断办法：和环境里的 Cookie 对比——登录过的环境 zhidao.baidu.com 下一定有 BDUSS。
  3. 转存提示"该账号无网盘登录态"，是 pan.baidu.com 没登录，不是环境坏了。 软件会自动跳过该账号并把原因写进运行日志。

⭐ 换电脑 / 重装后防重复答题（重要）

  1. 软件的答题历史（答过哪些题、抽题进度、题库）存在数据目录，不在软件文件夹里：按 Win+R 输入 %APPDATA%\zhidao-answer-studio 回车即可打开。
  2. 换电脑/重装前，把该文件夹整体拷贝到新电脑的同一位置（%APPDATA%\zhidao-answer-studio），再安装/解压新软件——历史答题记录全部恢复，抽题不会重复。
  3. 不拷贝的话，新电脑会当作全新开始：重新爬题爬回来的还是活动页那批题，答过的会被再次抽中（软件会在抽题时尽量排除已提交/已生成过的，但前提是数据目录里有历史）。
  4. 更新软件版本时不需要动数据目录：安装新版或替换软件文件夹即可，答题历史始终保留。

⚠️ 安全红线（务必遵守）

  1. 新账号首周每日提交 ≤ 5 条，账号稳定后再逐步放到 10~30 条。
  2. 保持「操作间隔」默认值（8~20 秒随机）—— 注意这项只在「比特窗口」运行模式下生效； 纯协议模式的条间间隔约 1 秒，如果你担心风控，请给账号配「账号代理」并错开时间跑。
  3. 遇到「安全验证」立即停下手动处理，绝不要让程序连续重试。
  4. 一键自检（比特环境页按钮）可随时验证整条链路，不消耗账号额度。

🔀 多账号隔离：到底隔了什么

很多人以为「换了 Cookie 就等于换了账号身份」——不是的。把三个层面拆开看：

  1. 登录态（Cookie）：每个账号各自一份，互不影响。这是唯一真正"跟着账号走"的东西。
  2. 出口 IP：只要在同一台电脑、同一个网络，所有账号就共用同一个 IP——用比特浏览器也一样，除非你在比特里给每个环境配了代理。
  3. 浏览器指纹：Cookie 里不含任何指纹。指纹是"请求发出去那一刻由客户端生成的"—— 所以从比特复制来的 Cookie 跑纯协议，并不会带上比特的指纹。 只有请求真的从比特窗口里发出去，才用得上比特那套隔离。

三种跑法的对比：

  1. 纯协议（默认，推荐） —— 内存几乎为零、速度最快（上传一批 0 秒 vs 窗口 6 秒）。 代价是所有账号共用 IP 和同一份网络指纹，所以务必错开时间跑。
  2. 比特窗口 —— 每个环境一套指纹，隔离最彻底；代价是内存（每个窗口几百 MB），且仍共用 IP。
  3. 纯协议 + 账号代理 —— 每个账号一个出口 IP，是性价比最高的"真隔离"： 在设置页「账号代理」里按 账号=代理地址 一行一个填写即可（支持 http / socks5）。

⚠️ 最重要的其实是"别让多个账号同时做同样的事"。 百度知道的风控主要看行为而不是设备：同一 IP 下多个账号在同一时段、用雷同内容做同样动作，才是真正的触发点。 程序已经保证同一时间只跑一个任务（点两次「一键全自动」第二次会被挡下）。 账号之间默认串行，天然留有间隔 —— 但如果你在设置页把「账号并发」调到大于 1，这个间隔就没有了： 那时必须给每个账号配不同的出口 IP（设置页「账号代理」），否则等于把自己摆到风控最敏感的特征上。
